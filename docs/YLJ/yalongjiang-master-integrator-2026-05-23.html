对赌算法
allmeta 持总盘对赌，Ontology + Eval Metric 把分摊算法工程化。 每个 ISV 的 Agent 都有独立 Eval Metric (盘古的预测精度、SCADA 的数据完整率、ERP 的写入成功率)， Reflection Agent 每周把实绩归因到各 Agent · 进入对赌结算。"ISV 拖后腿"不再是定性指控，是可量化的扣分项。
政治备注
底座选型 ≠ 纯技术决策。 L4 信创/云这一行尤其敏感：中联金灯塔是雅砻江股东背景，华为云是战略协同 ISV，私有机柜是合规底线。 Pod 在内部对齐时要把"谁先谁后"作为 DS 项 (不是技术项) 处理 —— Kenny 在场，DS 主导，技术只列约束。

项目期 · 一次性建设

三步法 · ISV 在哪一步进场

步骤 1 · 业务梳理

ISV 数据 / API / SLA 对齐

SCADA 厂 ERP / ECore 气象局 检修系统
不到场的 ISV 不签梳理纪要。必须把数据形态、API 节奏、SLA 写入梳理输出，作为后续 Ontology 映射的源契约。
步骤 2 · Ontology 构建

ISV 数据形态映射到 Schema

Neo4j (落地) SCADA 时序 → 实体属性 ERP 主数据 → 关系 盘古输出 → 事件
ISV 不需要懂 Ontology，但必须接受："你的数据 / 事件在 Ontology 里长成什么样"由 allmeta 定义，ISV 配合 Connector / Tool 包装。
步骤 3 · AgentGen

Worker 调 ISV 的 Tool / API

盘古 → 气象预测 Worker SCADA → 设备健康 Worker ERP → 调度执行 Worker
AgentGen 自动生成的 Worker 蓝图把 ISV 能力包装成 Tool / Tool 注册即 ISV 的入场凭证。注册过 = 接入合约成立。
